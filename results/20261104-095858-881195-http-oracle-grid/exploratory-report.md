# 探索性口径重分析

接纳当前 HC 数值作为探索性可用候选；原数值结果与严格报告均保留。H4096、完整相同输出、D=6。

**主要发现：P16 选 CC，P64 选 HC；G 未改变最优执行路径。提前准备相对返回后准备的额外收益尚未体现稳定优势。**

以下为返回后到完整响应的中位数，单位 ms；G 为服务器延迟目标。

| P | G | 不提前准备 CC | 返回后准备 HC | 提前准备 HC | 提前 HC ready/3 |
|---|---|---|---|---|---|
| 16 | 0 | 1442.5 | 2578.4 | 2596.9 | 1 |
| 16 | 50 | 1427.3 | 2759.0 | 2556.3 | 3 |
| 16 | 200 | 1446.0 | 2603.9 | 2638.9 | 3 |
| 16 | 500 | 1440.3 | 2571.9 | 2600.0 | 3 |
| 64 | 0 | 3791.4 | 1971.8 | 1996.5 | 3 |
| 64 | 50 | 3738.6 | 1971.5 | 1999.3 | 3 |
| 64 | 200 | 3864.0 | 1906.2 | 1979.5 | 3 |
| 64 | 500 | 3986.3 | 1934.9 | 1901.7 | 3 |

P64 提前 HC 相对返回后 HC 的 Tool 发起到完整响应收益（正数更快）：
- G=0：-17.9ms。
- G=50：-19.5ms。
- G=200：-66.6ms。
- G=500：+46.9ms。

联合 Oracle（允许显式准备/等待）在 P16 全部选择 CC；P64 在 G=0/50/200 选择返回后准备 HC，G=500 选择提前准备 HC。这是三次完整重放中位数的经验最小值，不能把小差异作为确定策略边界。

当前在线 Router 的差距仍需要放宽准入后重跑：原 cost_aware 运行因为数值门槛从未接纳 HC，也未提前准备。现有强制路径证明可选路径的潜力，不能替代该策略本身的在线测量。

解释边界：
- 原在线 Router 因旧门槛禁用 HC，cost_aware 分支未提前准备且全部选 CC；不能把离线改资格当成在线放宽门槛后的实测
- 此处 Oracle 是完整实测路径重放的经验最小值，允许显式返回后准备或等待；不同于旧 Router 仅接纳 ready 的选路 Oracle
- 三次重复、无线 HTTP 实际 Gap 波动；几十毫秒差异不足以证明提前准备的稳定收益
