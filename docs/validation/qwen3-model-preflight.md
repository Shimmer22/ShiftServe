# Qwen3-8B模型准入与正式扫描启动

2026-11-13，手机使用Termux SSH持锁串行执行；不更改设备设置或频率，无ADB回退。默认模型已切换为Qwen3-8B Q4_0，配置、执行命令和矩阵见[指南](../guides/qwen3-model-costs.md)。

## 模型与功能

手机模型完整SHA-256为`7578dd44850f97bea0f89d6553a2b3260de07185aa363852dbbe582539ce8066`，与本地及上游LFS摘要一致。安装完成并释放安装锁。实际399个张量中，253个Q4_0、145个F32、输出头为Q6_K。HTP条件仍是offload，保留CPU attention和输出头，不能称为全算子纯HTP。

双驻留诊断的CC/HH/HC/CH四路径均完成两轮自由生成，每轮输出`{"code":314159}`，EOG已提交，第二轮直接复用上一轮上下文。检查点恢复后的状态和logits逐值一致。H4096恢复、有限logits与对照亦通过，cosine约0.999658；这不是完整任务质量或严格跨后端输出分布等价证明。

## 双驻留不能作为无换页计算基线

最初H4096/P40/D8预热中，CPU decode窗口增加71510次major faults，swap达到2246056 KiB。功能正确不等于性能条件可用，因此没有用这一组启动正式纯阶段扫描。原始结果保留在`results/20261113-qwen3-8b-dual-resident-diagnostic/`。

## 单驻留通过实际长度检查

单驻留版本CPU/HTP各自的两轮JSON、记忆与检查点通过；短H32/P8的cosine约0.999634，两个后端计时窗口均无新增major faults且swap为0。

H4096/P40/D8检查的cosine约0.999658，NRMSE约0.02617。CPU、HTP的prefill窗口和连续decode窗口均为0新增major faults；末端swap均为1208 KiB。历史bootstrap约291.7秒，单独记录，不计入prefill或decode。以上是准入/预热数据，不替代十次正式重复的均值或稳定性判断。

该版本逐点释放旧context/model再加载目标后端，32-token预热、加载与释放均在阶段计时之外；每条路径的prefill/decode仍使用同一context。加载后的模型从同一个CPU权威快照恢复。切换后释放资源的实测记录保存在每行`backend_setup`；短检查时释放后进程RSS回落到约30 MiB。

## 正式采样协议

固定H4096、context4608、batch128、F16 KV、CPU6线程、HTP主机4线程，OPBATCH1024/OPQUEUE16，KV整理和预搬移关闭。P为24至64逐整数，加66/68/72/80/96/128，共47点；每点每后端十次，轮内固定seed乱序，逐点CPU/HTP先测恰为5/5。不是将两个后端分成两批。D固定P40，逐token连续执行到320，在11个检查点记录累计时间，重复三轮。

完整473个配对请求先落盘为`schedule.json`，逐个响应原子保存。正式采集已启动，并已产生完整CPU/HTP配对文件；最终完成与结论仍须等待全量验收。独立监督器保留心跳及子进程进度，不以进程已启动冒充实验完成。

阶段结束先保存阶段CSV和`stage-summary.json`，随后另显式进入双驻留测状态交接，并重验HC/CH。单驻留阶段表不能直接替代双模型常驻的在线路由成本；资源条件必须与表一起解释。

## 失败与修复

- 初次长SSH流被重置，原始接收进程与锁残留。改为32 MiB有限分块、逐块SHA-256、归属校验与接收器清理、有限网络重试；手机端以64 KiB写入后模拟丢应答，重试覆盖同一块并核验通过。不是通过更换模型或后端掩盖失败。
- 系统Python直接读取超长含中文参数行时报告源码编码错误，尽管文件UTF-8解码有效。拆成逐参数行后，四个入口的实际CLI启动检查通过；新增回归测试避免只用编译字符串检查遗漏此类错误。
- 原始失败日志、安装尝试、双驻留诊断和新采样结果分别保留，未覆盖旧数值。
