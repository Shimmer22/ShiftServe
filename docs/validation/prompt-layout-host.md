# 主机验证：工具说明重排与历史前缀共享

结论：可以共享，而且已经观察到真实缓存命中。最有效的条件并非仅把固定说明前移，而是保持初始工具目录与历史序列稳定，把新工具说明保留在原公开轮次的追加消息中。这是私有适配器布局实验，尚未证明完整任务准确率无损。

## 条件与范围

复用 wins 的 RTX 4090、既有 Qwen3.5-9B BF16、vLLM 容器及 tokenizer。选原轨迹全部 18 个新增函数公开边界，四种布局，每条件每边界测一次，顺序按边界轮换，共 72 次目标请求。未修改手机实验，也不提供手机 GPU 对照结论。

四条件为 native、rules_first、append_docs、append_docs_stable_history。后两个条件冻结最初 tools 目录；原来在 user 公开消息中的新增文档完整保留，公开时点不变，未向模型提前公开未来工具。最后一个条件还保留历史 assistant 的空 think 标记，避免跨用户轮重新渲染时删除它们。

每条件清空私有引擎 prefix cache，再用变换后的上一请求及相同原始生成 token 预热，随后测本次目标请求。预热、布局变换和 tokenization 不计入表内 prefill。允许调用的工具集合按该轮实际公开范围校验。生成结果只保存和解析，没有执行生成动作。

## 实测结果

| 布局 | 逻辑 P 中位数 | 实际缓存命中边界 | 累计 server prefill | 调用与原版一致 |
|---|---:|---:|---:|---:|
| 原生模板 | 1398.5 | 0/18 | 9.950 s | 18/18 |
| 固定规则移到工具目录前 | 1204.5 | 2/18 | 9.180 s | 17/18 |
| 初始目录稳定，新增说明只在公开消息追加 | 562.5 | 8/18 | 6.595 s | 16/18 |
| 上一条件＋历史空 think 标记稳定 | 232 | 18/18 | 1.473 s | 16/18 |

最后一个条件累计 prefill 为原版的 14.8%，约 6.76 倍加速。该比值仅针对这批单次目标请求的 server prefill；不是完整任务 E2E，不是手机 CPU/HTP 性能。

最后一个条件累计实际缓存命中 74976/84204 个输入 token，约 89.0%；逻辑 H/P 与物理缓存命中不是同一个数。物理缓存的检查点位置、粒度及 Mamba/GDN 状态影响中间前缀复用。原版 0/18 仅指本次“清缓存→上一冻结历史预热→当前请求”协议下的结果，不能推断引擎在所有请求上都不缓存。

## 用户选中的具体边界

`multi_turn_miss_func_194/t05-s00`：

| 条件 | 逻辑 H | 逻辑 P | 实际命中 token | server prefill |
|---|---:|---:|---:|---:|
| 原版 | 2750 | 2764 | 0 | 0.634 s |
| 固定规则前移 | 2944 | 2570 | 0 | 0.636 s |
| 新说明追加 | 4952 | 431 | 4752 | 0.108 s |
| 新说明追加＋稳定历史 | 5241 | 186 | 4752 | 0.107 s |

这里可以真实复用 4752 token。最后两个条件逻辑 P 不同，但实际命中相同；更大的逻辑 H 并未进一步变成更多物理命中。这也说明不能简单用 2764→186 来声称实际计算量下降同一比例。

原版当前请求没有调用工具；最后一个条件调用了当轮刚开放的 `contact_customer_support`。原任务先前官方评分失败，错误类型为 empty_turn_model_response。新调用可能符合用户目标，但本次没有执行该动作或重跑整个任务，不能据此判定它已修复任务。

## 响应检查与局限

原版 18/18 复现了原始下一步工具调用。最后条件 16/18 调用一致，两个变化在原先未通过任务：`miss_func_15` 从 echo 改为 touch，`miss_func_194` 从无调用改为客服调用。对原先通过任务的 8 个目标边界，最后条件的调用 8/8 一致；这只是单边界一致性，不是新布局的 8 题完整通过率。

仅追加说明、不稳定历史的条件还改变了原先通过任务 `miss_func_17` 的 ls 参数，因此这些布局不能只凭缓存命中就合入默认流程。参数顺序不同但名称/参数值相同按同一调用统计，调用序列仍保持有序。

72 个响应均未超输出上限，未出现解析失败或调用未开放函数。完整文本不要求逐字相同。总输出 token 从原版 2010 变为最后条件 1900，因此完整 HTTP 用时的差异不能归因于 prefill；本报告不据此宣称 E2E 加速。

这是单次、冻结历史、旋转条件顺序的机制验证，没有重复运行误差范围，未测布局处理成本、完整任务质量或手机状态迁移。主机权重 BF16 与手机 Q4 也不同。

## 文件与复现

- `preflight.json`：18 个边界的逻辑 token 前缀。
- `measurements.json`、各任务/step/布局子目录：完整 prompt、预热响应、目标响应、指标差分。
- `summary.json`：逻辑 P、真实缓存和响应一致性汇总。
- `server-command.json`、日志、实现摘要：运行配置与来源。
- 配置：`configs/prompt-layout-host.json`；机制：`src/a2o/profiling/prompt_layout.py`。

运行入口及服务器生命周期见 `docs/guides/prompt-layout-host.md`。汇总：

```sh
python scripts/analyze/prompt_layout_host.py results/20261109-prompt-layout-host
```

服务完成后已停止，主机 GPU compute 进程已清空；原始失败调试日志保留。后续应先检查完整多轮任务质量，再决定是否作为适配器修复或研究机制继续，当前不改变手机基线。
