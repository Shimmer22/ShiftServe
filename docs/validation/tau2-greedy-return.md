# τ²-bench 贪心继续准备实验

结论：本批6个预选边界中，贪心策略实际完成18次HTP prefill→CPU decode，18次均快于同轮CPU和Full HTP；相对本轮CPU累计比值1.258×，相对Full HTP为1.608×。阶段选择与同批事后oracle一致，尚不代表完整任务E2E或其他H/P分布的最优策略。

## 配置与选择规则

复用[首轮pilot](tau2-pilot.md)的同6个任务来源边界、原始H/P/D及实测工具等待G。Qwen3.5-9B Q4_0，context16384，CPU6线程、HTP主机4线程，batch128、F16状态；不做pad、KV整理或预搬移。每个边界3轮，每轮CPU/HTP/Route位置轮换，共54个条件测量。

准备策略保持always-prepare。返回时比较：

```text
CC = CPU锚点恢复 + CPU prefill
HC = HTP prefill + HTP→CPU回迁
剩余准备 = ready时为0，否则max(独立准备预测 − 已流逝时间, 0)

剩余准备 + HC < CC：继续等待，完成后走HC
否则：放弃准备，走CC
```

等待预算为CC−HC，预算耗尽仍未完成则转CPU；真实设备错误直接失败。等待、恢复、prefill、回迁、decode与清理尾部分别计时，等待与回迁计入返回后总耗时。两条路的decode都在CPU，选择式省略共同decode项。

继续使用首轮独立成本表及预测，未使用正式响应实测耗时做事后选路。原H/P缩放校验标记仍为false，按用户明确接受预测可靠性的要求记录 `allow_unvalidated_prediction=true`，不再用极大HTP成本封锁选择。剩余时间估计只读独立预测与已流逝时间，不读取本轮准备的未来完成时间。

## 完整性与机制

- 54/54条件测量完整，原始JSON、精确H/P/D、输入来源与二进制/源码身份复核通过；条件位置轮换符合计划。
- 12个HF/GGUF输入和输出token序列一致；正常响应通过。正式计时前验证继续、放弃、已ready、等待超时四条分支，短机制请求不纳入统计。
- 正式Route共18次，返回时全部pending；18次均选择继续准备，等待后全部ready并走HC，等待超时0次。
- 每次HC均记录真实HTP→CPU回迁，使用完整状态字节核验助手。输出采用teacher forcing，状态核验不等于自由生成质量通过。
- 等待累计8.719s，中位数0.197s，范围0.144–2.103s；回迁累计6.275s。两项合计14.994s，占Route返回后累计耗时1.316%。
- 手机服务已退出，模型锁释放，无活动模型，日志已回收；状态缓存继续保留在手机。只使用Termux SSH，不改变设备设置或频率。

## 与同批阶段oracle对照

逐边界逐轮计算 `min(CPU prefill,HTP prefill)+min(CPU decode,HTP decode)`，18次全部选HTP prefill和CPU decode；与贪心路径18/18一致。

| 统计 | 累计耗时 s |
|---|---:|
| 阶段oracle，仅prefill+decode | 1157.037 |
| Route，仅prefill+decode | 1124.519 |
| Route，含等待与回迁等返回后总耗时 | 1139.543 |

Route纯阶段比拼接oracle低2.81%，返回后总耗时也比拼接值低1.51%。这不表示超越严格理论下界：oracle取另两次条件的阶段观测，跨执行拼接会受运行状态和测量波动影响，而且不包含等待及迁移。可支持“本批路径选择一致、时间接近”，不能据此称策略全局最优。

## 复现与证据边界

执行入口 `scripts/collect/tau2_greedy.py`，实现位于 `src/a2o/profiling/tau2_greedy.py`，策略位于 `src/a2o/native/scheduling/greedy_return.h`。贪心、超时、版本绑定及错误传播的原生测试入口为 `tests/test_greedy_return.py`；旧异步与有限等待测试一并通过。

本地证据目录 `results/20261112-tau2-greedy-return/` 保存plan、成本表引用SHA、预测、12个token检查、四分支验证、18个配对响应、计时CSV、完成汇总及收尾记录。54个条件的数据一致性和计时加和已从原始JSON重新复核。原始结果、二进制、缓存和模型不入Git。

本轮为冻结token＋外部实测G的定时回放＋真实异步状态准备/等待；用户模拟器仍是主机本地9B自定义配置。未执行生成工具动作，不检验手机完整任务成功率、历史记忆语义或live E2E。对预测误差接受的决定不等于预测准确性通过验收。
