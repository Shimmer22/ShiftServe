# 手机评测 Pre-flight

新启动手机评测服务、启动独立探针或接入已启动的服务执行回放时，运行同一套后台负载检查。正式手机入口使用 Termux SSH，并在已有模型锁的保护下检查。复用服务时，门禁通过锁归属、PID 文件和该 PID 的可执行文件路径确认评测进程。仅该服务 PID 及本次采样 shell、`top` 进程从 CPU 合计中排除。

- 以 Android `top` 的单逻辑核 100% 口径，检查 Termux UID 可见进程。采样取两个完整的 1 秒区间，每个区间分别合计非测试进程 CPU。任一区间超过 15% 即中止，恰好 15% 可通过。
- 任一采样表发现 `tr` 即中止，包括零 CPU 的 `tr` 及可识别的 `toybox tr`、`busybox tr`。采样命令失败、进程表不完整或复用服务身份校验失败同样中止。
- 每次检查在运行目录保留独立的 `phone-preflight-*.txt` 和同名 JSON，含采样时间、进程明细和拒绝原因。ToolSandbox 的 Docker 采集由控制端完成手机 SSH 检查，容器保存交接摘要。
- Termux SSH 可见性受 Android UID 隔离限制。仍显式使用 ADB 的历史脚本按该传输可见进程检查；Termux 入口无自动回退。
