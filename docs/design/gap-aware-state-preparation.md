# Tool Gap 中面向不确定需求的状态准备

研究判断：REFINE。候选为系统调度机制，尚未完成新颖性审计或跨模型收益验证。

## 跨模型存在的约束

1. 自回归推理状态依赖其前面的上下文。前部 token 真正改变后，后方相同文本的旧状态通常不能直接复用。稳定模板可消除无意变化，但不能消除新观察依赖。
2. 工具发出时知道当前历史与调用参数，真实返回内容、追加量 P 和返回时间 G 尚未全部获知。等待期间可以准备已知状态；依赖未知观察的计算必须等待，或经过投机验证。
3. 在 CPU/HTP 异构执行且有非零准备、恢复、迁移成本时，哪条执行路径更快依赖实际工作量及已有状态。准备选择先于部分需求信息，返回后选择依赖准备结果，二者耦合。

上述结构不依赖特定模型名称。实际收益只在存在足够真实 Gap、准备成本和路径成本交叉时出现；不存在所有 mobile agent 都必须获得收益的保证。保持单后端且状态始终驻留是必要负对照。

## 一个机制候选

将工具等待视为有预算的执行选项准备窗口：调用时根据历史 H、工具类型和参数、当前状态与历史统计，估计 P/G 的联合分布；在等待期间选择不准备、立即准备或延迟准备 HTP 状态；返回后依据实际 P、合法完整状态与剩余准备成本选择 CPU/HTP。

不预测工具返回正文，不自动执行动作。候选状态绑定模型、模板、token 前缀、状态版本与后端兼容信息。恢复时验证权威输入，失败则采用合法基础路径。KV、recurrent、conv 等状态由后端完整导出/恢复；不假设任意状态可以跨模型或跨后端通用，不假设可任意切分或拼接。

在首先忽略资源干扰的简化模型中，令准备动作 a 在返回时产生剩余准备成本 R_b(a,G)，后端路径 b 的其余成本为 C_b(H,P)，则目标是最小化 E[min_b{R_b(a,G)+C_b(H,P)}]，并约束准备能量与内存。真实测量还要计入工具变慢、验证、取消、同步和状态提交成本。完整任务还包括工具耗时与 decode；返回路径收益不能直接等同 E2E 收益。

重要边界：如果准备完全无成本、无干扰且不阻挡 CPU，always-prepare 已经保留全部可行路径；选择性准备不应声称进一步降低延迟。额外价值必须来自可测的资源约束、干扰、启动时机或准备完成度差异，或表现为同延迟下更少能耗/内存。

## 当前证据与不足

- 冻结重放 72 次 route 选择中 CPU 45 次、HTP 27 次；存在路径选择差异。45 次 CPU 选择不等于先验准备一定浪费，因为准备保留了另一执行选项。
- 该批记录的 route 准备合计约 15.27 秒，中位数约 166 毫秒；准备排除在 ready-state 目标计时外，不能用来宣称真实 Gap 已隐藏它。
- BFCL 513 个真实沙箱工具边界 G 中位数约 0.193 毫秒，远不足以支持这一级准备成本的完全重叠。必须保留这一不利结果。
- 当前没有实际 P/G 联合分布可预测性、工具干扰、能耗和 on-demand hybrid 的完整对照。不得把模拟延长 Gap 当作真实工作负载收益。

## 与已有工作的边界

[Agent-X](https://arxiv.org/html/2605.10380v1) 的 PromptWeaver 重构前缀以提高缓存复用，ExSpec 基于示例生成 draft 并选择性验证。本候选保持权威输入，研究等待窗口内的状态准备与返回后异构选路。二者有机会组合，但不是已证明的独立贡献。

[TokenCake](https://arxiv.org/html/2510.18586) 已使用 function-call 事件、成本收益卸载及预测上传时机隐藏传输延迟。不能把“工具期间搬状态”申领为新机制。最小待验证差异是：返回结果长度决定不同 CPU/HTP 路径的收益，因此准备策略需要针对未来选路的价值决策。若 TokenCake 式预取加简单成本阈值已覆盖收益，应缩小或放弃独立机制主张。

本次初步检索受 connector 缺包与部分 429 限流影响，未完成 idea-spark 全流程及完整 collision audit，不声称新颖性已验证。

## 最快的证伪实验

先做带真实 P/G 和状态准备计时的 oracle 上界，补齐 CPU 常驻、HTP 固定、返回后才准备的 hybrid、always-prepare+相同返回选路、工具时长驱动预取+相同返回选路。所有条件修复同样的模板/锚点问题，采用相同资源预算并统计全部开销。

若 oracle 在合理资源预算下仍不能胜过简单基线的延迟/能耗权衡，则不训练预测器。若 oracle 有价值，再用按任务划分、仅调用时可见特征的 P/G 分布估计实现在线策略，测真实 E2E、p95、能量、峰值内存与完整任务质量。

跨模型验证应覆盖纯 attention 模型与混合 recurrent 模型；按设备支持明确配置 CPU/HTP，设备不可用直接失败。后端仅替换完整状态操作与成本模型，不改变决策问题。单后端常驻、近零 Gap、始终选同一路径是负对照。自然长 Gap 工作负载未获授权前不操作用户 App 或数据。
