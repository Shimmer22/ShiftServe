# 手机推理和采集链路检查

2026-11-21。范围覆盖主机启动与续跑、手机请求、分词、状态恢复和交接、计时、日志及论文取数。当前 T6 的 G=0 批次仍运行既有封版。源码变动需单独构建和验证。

## 本轮修改

| 链路 | 处理 | 保留的保证 |
| --- | --- | --- |
| 分词和 Decode | 分词先提供有界输出空间，常用长度直接得到结果。只有空间不足才按返回长度重试。Decode 错误字符串只在失败时构造 | 同一模板、分词选项、token 序列和错误检测 |
| 冻结回放 | 直接比较 JSON token 与分词结果，避免复制整条预期输入。单列 `frozen_validation_ms`，同时保留实测墙钟和减去这段校验后的诊断值。异步提交移动请求对象，避免再次复制长消息和 token 数组 | 进入推理前仍检查输入序列、Decode token 范围和容量。响应仍可复核实际执行序列 |
| KV 迁移和缓存 | 服务默认仍使用导入长度和末位置核对。独立回放缓存按服务配置核验，在内存命中时直接借用快照，磁盘命中直接读入最终缓冲。显式拒绝零字节状态导出 | 磁盘缓存仍检查模型和构建、输入 token、状态字节数及校验和。需要全量回读的诊断入口可显式启用 |
| 三路标定 | 冻结 Decode 跳过未使用的贪心扫描及 HTP logits 回传。仍为 CPU/HTP 数值对照采集 logits，单列采样时间。新配对协议返回实际交接字节数，采集默认轻量核验，分析器兼容已验收的旧协议 | 保留实际 HTP 图、非零交接、裁剪、冻结 token、0.99 数值门槛及服务端导入检查。旧协议仍使用原字节回读日志验收 |
| 资源和状态提交 | 启用内存账本时复用同一检查点的进程资源读取。单列 `state_commit_ms`，捕获新旧锚点切换；原 `total_ms` 保持原墙钟定义 | 保留准备、Prefill、交接和 Decode 内存观察点，对比可追溯 |
| SSH 和轮询 | 启动健康检查、启动内存账本读取和成本安装沿用同一个转发地址。HTTP 错误与连接故障分开。异步启动和轮询共享一个总期限 | 保留锁所有者、实际 PID、模型和运行时身份核对，无 ADB 回退 |
| 停止和续跑 | 确认服务停止后回收已有日志，记录缺失文件并清理自有锁。先核对续跑计划再写元数据，固定强制路由、轮数、在线模式和成本表 SHA。静态组已有完整轨迹可复用；断过的自适应组整组归档后重跑 | M1 在同一组跨轨迹保留后验，避免把一次重启丢失后验后的轨迹接入旧组 |

## 仍需区分的测量口径

- 冻结校验的减时字段用于分解开销。G=0 时 HTP 准备可能与校验并行，旧墙钟或新减时值都无法单独推断完全去掉校验后的路由决策。
- T6 的 G=0 表示宿主没有主动等待。两个请求间仍有传输和重试，实际手机侧准备窗口需用设备时钟另测。强制静态 HC 必须完成准备，超出的等待由服务记录。
- 内存账本保留在当前实验。异步准备线程完成恢复后还会做采样，之后才能就绪。因此带账本的 G=0 选路受采样影响，不能用事后扣账本耗时代替轻量时延实测。内存表是指定检查点的采样峰值，异步准备与启动的其他观察值仍可在原始日志核对。
- `total_ms` 截止在锚点提交之前。新字段单列锚点提交，HTTP 序列化和宿主通信仍需独立计时。旧记录不能重建这些未单列的耗时。
- 减少冷 Prefill 采用跨组快照、改变 KV 交接或减少中间 logits 计算都会改变实际工作负载，应单独验证状态、数值和配对口径。
